# YHU News - React + Vite

```bash
npm install
npm run dev      # http://localhost:5173
npm run build
npm run preview
```

Routes: `/` home, `/category/:slug`, `/article/:id`, `/search?q=`, `/about`, `/contact`, `/privacy`, `/terms`, `/admin`, `/admin/add`

- The homepage and categories display stories written and published manually through the admin panel. No external News API or weather API key is needed.
- The navigation and admin publishing categories include India, World, Cities, Movies, Election, Politics, Business, Technology, Sports, Entertainment, Education and Lifestyle.
- Admin login, article management, and image delivery use the project's internal API. Production article storage uses Neon Postgres; local development uses `data/articles.json`.
- The article sidebar provides a Hindi translation using MyMemory, with Google Translate as a fallback when MyMemory is unavailable; only the article currently being viewed is sent to the translation provider. Set `MYMEMORY_EMAIL` to a contact email you consent to share with MyMemory to increase its daily translation quota.
- Public pages load as separate JavaScript chunks, use page-specific metadata and article structured data, and reveal content as readers scroll. Scroll effects respect reduced-motion preferences.
- `public/robots.txt` and the `/sitemap.xml` endpoint provide search-engine crawl guidance and include published article URLs.
- Set `PUBLIC_SITE_URL` to the public canonical origin if it differs from `https://yhonewsindia.onrender.com`.
- Keep `DATABASE_URL`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, and `ADMIN_SESSION_SECRET` private. Render provides the session secret from `render.yaml`; set the database URL and admin credentials in the Render dashboard. `MYMEMORY_EMAIL` is optional and is sent to MyMemory for translation quota identification.

## Deploying to Render

1. Push the project to GitHub, then in Render choose **New > Blueprint** and select this repository. Render reads `render.yaml` to create a Node **Web Service**. Do not deploy this app as a Static Site: static hosting serves the frontend files but cannot run the Admin API.
2. Create a Neon Postgres database and copy its pooled connection string with SSL enabled.
3. In the Render service environment settings, set `DATABASE_URL`, `ADMIN_EMAIL`, and `ADMIN_PASSWORD`. `ADMIN_SESSION_SECRET` is generated by the Blueprint; do not replace it with a public value.
4. Deploy. The service builds with `npm ci && npm run build` and starts with `npm run start`. Render checks `/api/health` to verify that the Node server and API are running.
5. Open `/admin`, sign in with the configured credentials, and publish articles. Published news and uploaded images are stored in Neon, so they survive service restarts and redeploys.

## Deploying to Vercel

1. Import this GitHub repository in Vercel. Vercel detects the Vite app and uses `vercel.json` to build the `dist` directory and route client-side pages.
2. Create a Neon Postgres database and copy its pooled connection string (with SSL enabled).
3. In Vercel, add `DATABASE_URL`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, and a long random `ADMIN_SESSION_SECRET` to the Production environment variables. Never commit or share these values.
4. Redeploy. The API creates the `yho_news_articles` table automatically on first use and imports `data/articles.json` once if the table is empty.
5. Sign in at `/admin`, create an article, upload a JPG, PNG, or WEBP image, and choose Publish. Published stories appear on the homepage and their matching category page; drafts remain private.

For local admin access, create a `.env` from `.env.example` and set the admin values. Local articles are written to `data/articles.json`; local changes are not automatically copied to the production database.
